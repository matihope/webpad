# 2026-11-01: Project start, milestones 0 and 1

## Decisions
- The phones drive **real OS gamepads**, the host must be **cross-platform**, and the server is written in **Rust** ([ADR 0001](../decisions/0001-rust.md)).
- Transport: WebSocket carrying binary full-state frames ([ADR 0002](../decisions/0002-websocket-binary-protocol.md)).
- macOS gets a keyboard backend instead of a virtual gamepad ([ADR 0003](../decisions/0003-macos-keyboard-fallback.md)).
- The reconnect token is stored in `sessionStorage` rather than the `localStorage` the plan named. Reloads keep the slot, and two tabs stay two players.
- Message type numbers are Hello 0x01, State 0x02, Ping 0x03. The plan listed State first, but docs/protocol.md is the source of truth.
- Graceful shutdown is skipped. Open sockets would keep Ctrl-C waiting, and the OS unplugs virtual devices when the process exits.

## Changes
- Scaffolding: git repo, Cargo crate, README, AGENTS.md, CLAUDE.md (`@AGENTS.md`), and the docs tree.
- Server: `main.rs` (CLI, QR, TCP_NODELAY, reaper), `server.rs`, `protocol.rs`, `session.rs`, and `backend/{mod,log}.rs`.
- Phone UI: `web/` with floating sticks, D-pad with diagonals, ABXY, shoulders, menu buttons, L3/R3, slide-between-buttons, haptics, RTT, fullscreen and orientation lock, rotate overlay and the iOS hint.
- Smoke tests: `tools/fake-phones.mjs` (protocol) and `tools/ui-smoke.mjs` (headless Chrome over CDP).

## Verification
- `cargo test`: 8 out of 8 pass (protocol round-trip and layout, session slots, takeover, release, grace and reap, full-server handover). `cargo clippy --all-targets` is clean.
- `tools/fake-phones.mjs` against `--max-players 2` showed:
  - slots 0 and 1 assigned, and the third client rejected as full (0x84 01);
  - pong echoed;
  - a reconnect with the token got slot 0, the stale socket's B press was ignored, and the new socket's X was applied;
  - the silent client was dropped after the 1.5 s heartbeat with its inputs released.
- `tools/ui-smoke.mjs` at 844×390 with mobile touch emulation showed in the server log:
  - A held while the stick moved to +0.7/+0.7 (stick up gives positive Y, as intended);
  - sliding A onto B switched the press to B;
  - D-pad down-left gave a diagonal;
  - LT and RT were pressed together;
  - everything released on lift.
- Screenshots looked right for the start overlay, the controller and the portrait "rotate" overlay.
- **Not yet tested:** real phones (Android Chrome, iPhone Safari and home-screen mode), actual Wi-Fi latency, and reconnect after locking the phone.

## Second phone test (iPhone, LAN 192.168.0.32): D-pad redesign
- The user said the rest of the UI was fine, but the **D-pad looked odd**. It was four separate bordered boxes: the borders overlapped, the center was hollow, there were no arrows, and it sat close to the home indicator.
- It is now one SVG cross: an outlined shape with arrows, a center dimple, and per-arm highlights clipped to the cross. JS sets `.up/.down/.left/.right` on `.dpad`.
- Gotchas:
  - A `<clipPath>` can't `<use>` a `<g>`; the reference silently fails in Chrome.
  - Percent `height` on a grid item, combined with `1fr` rows, made the rows grow to fit the SVG and pushed the layout off-screen. The fix was rows `minmax(0, 1fr)` and sizing the D-pad by width.
- Verified with `tools/ui-smoke.mjs` at 932×430 (iPhone Pro Max landscape): Down+Left registers, both arms and arrows light up, and nothing overflows. The new screenshot `3b-dpad` is taken while the D-pad is pressed.
- Not yet re-checked on the iPhone.

# 2026-11-01 (later): Commit, then milestone 1b, admin and auth

## Commit
- `88f6153` is the initial commit with milestones 0 and 1 and the D-pad redesign.

## Decisions (user)
- A separate optional **join code** goes into the QR, and an **admin password** protects Manage. They are independent ([ADR 0004](../decisions/0004-auth-model.md)).
- **With no admin password, Manage is open to everyone.**
- Extras the user asked for: identify player, live input preview, lock joining, player names.

## Changes
- **Routes:**
  - `/` is now a landing page (name, join code, Join or Manage); the controller moved to `/pad` (`pad.html`), and the admin page is at `/admin`;
  - API: `/api/info`, `/api/login`, `/api/logout`, `/admin/ws`, `/admin/qr.svg`.
  - The manifest's `start_url` is now `/pad`.
- **Protocol v2:**
  - the join code goes in `/ws?code=`;
  - new message `0x04 Name`;
  - new message `0x85 Slot`;
  - new message `0x86 Identify`;
  - Reject 4 (code), 5 (kicked), 6 (locked).
- **Sessions:**
  - Each slot is now a fixed pad plus a movable owner. Reordering swaps owners, so games keep the same controller indices.
  - Leases are found by connection id, so they follow swaps.
  - Each connection has an mpsc control channel (Slot, Identify, Close on kick). Taking over a slot drops the old connection's sender, which now really closes the old socket. Before, it lingered until a timeout.
  - A `watch` version drives the admin snapshots.
- **New module** `src/admin.rs`: optional password with an in-memory session cookie (HttpOnly, SameSite=Strict), a 1 s delay after a failed login, a same-origin check on the admin WebSocket, snapshots throttled to 15 Hz (and at least 1 Hz for grace countdowns), and the QR as SVG.
- **Web:**
  - CSS split into `base.css`, `pad.css` and `pages.css`; shared JS in `common.js`;
  - the controller gets a name field on the start overlay, a "stopped" overlay (wrong code, kicked, outdated), and a fullscreen flash for identify and moves;
  - the join code from the QR is saved in localStorage and removed from the address bar.
- **New dependencies:** `serde`, `serde_json`, the `qrcode` `svg` feature and the `clap` `env` feature.

## Verification
- `cargo test`: 18 out of 18 pass. The new tests cover swap (owners move, pads don't), a lease following a swap, moving into an empty slot, kick, unplug, lock, the snapshot, the new protocol frames, constant-time compare, cookie parsing, the login flow and the origin check. `cargo clippy --all-targets` is clean.
- `tools/admin-smoke.mjs` passed all 18 checks: info, the QR needing a login, a wrong password giving 401 after about 1 s, cookie, admin WS refused without the cookie, snapshot, names and live state, swap notifications, move into an empty slot, identify, lock with Reject 6 while a token rejoin is still allowed, kick with Reject 5, grace countdown, and removing all disconnected.
- `tools/fake-phones.mjs` passed all 9 checks, including wrong or missing code giving Reject 4 and the old socket being closed after a token takeover.
- `tools/ui-smoke.mjs` still works on `/pad` (multi-touch, D-pad diagonal, triggers). `tools/pages-smoke.mjs` screenshots looked right for the landing page (phone), admin login, and the admin page on a laptop and a phone, including the live preview of held buttons, stick and trigger.
- **Not yet tested on real phones:** reorder, identify flash and vibration, kick and the "Join again" screen, name entry on iOS, and the admin page in Safari.

# 2026-11-01 (evening): Steam Link question, ViGEm backend

## Context
- The repo was pushed to GitHub (`origin`), with commits `88f6153` and `0926068`.
- The user connected 2 phones while the server ran on the Mac in `log` mode, and the phones did nothing in Steam Link. That is expected: `log` creates no device.
- The game runs on **kolpa2 (Windows)** and is streamed to the Mac with Steam Link. The user asked whether Steam Link bridges controllers. It does, but only controllers the client OS sees, and macOS can't create virtual gamepads (ADR 0003). The decision is to **run webpad on the Windows game PC** with ViGEm.

## Changes
- `src/backend/vigem.rs` uses `vigem-client` 0.1.4 (Windows-only dependency). It plugs in one `Xbox360Wired` per slot and passes buttons and axes straight through, since the protocol already uses the XInput layout. Dropping the pad unplugs it. A missing driver gives a clear error message.
- `BackendKind::Vigem` is behind `#[cfg(windows)]`. `auto` tries ViGEm on Windows and otherwise warns and uses `log`.

## Verification
- `cargo check` and `clippy --target x86_64-pc-windows-gnu` on macOS are clean. The macOS build and its 18 tests still pass.

## kolpa2 facts (2026-11-01)
- The SSH session is **not elevated** (`net session` fails), so driver installs and firewall rules must be done by the user in an admin terminal.
- Windows Firewall is on for all profiles. git and winget are available.
- The user chose to install user-level rustup (GNU toolchain) over SSH and build from a GitHub clone.
